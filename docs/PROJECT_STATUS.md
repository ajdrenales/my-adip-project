resolved to newer releases instead.

## Known issues
- Docker is not installed in the Linux development container, so the Docker
  checks are run on the ThinkPad; both environments are now verified.
- Backend dependency drift on the ThinkPad is **resolved** in Milestone 0.1 (see
  above): the venv now runs Python 3.11.9 with all declared pins enforced.
- Frontend runtime drift remains: the ThinkPad runs Node v24.21.0 / npm 12.1.0
  while the README targets Node 20 LTS. The frontend tests and build pass, but
  the versions are not yet aligned to the README.
- The ThinkPad now has two Python interpreters and `py` defaults to 3.14 (the
  `*` marker in `py -0p`). The backend venv is correctly 3.11.9, but any
  `python`/`pip` run outside the venv will use 3.14.
- npm 12 on the ThinkPad reports "3 packages had install scripts blocked"
  (esbuild postinstall). The frontend build still succeeds because esbuild's
  platform binary is provided through optional dependencies.
- A transient Vitest artifact (`frontend/vitest.config.ts.timestamp-*.mjs`) can
  appear in `frontend/` during test runs and is not covered by `.gitignore`.
- `frontend/package.json` declares `vite ^6.0.5` together with `vitest ^2.1.8`.
  Vitest 2.x requires Vite 5, so npm installs a second, nested `vite@5.4.21`
  under `node_modules/vitest/`. This is development-only tooling, but it caused
  the `tsc -b` type conflict now worked around above and it produces 5 npm audit
  advisories (3 moderate, 1 high, 1 critical). `npm audit` reports the only
  remedy as a breaking dev-dependency bump (`vitest@5.0.3`); that upgrade was
  deliberately not applied in Milestone 0 to keep the change minimal and is
  recommended as a separate, individually verified task.
- `vitest.config.ts` is no longer typechecked by `tsc -b` (typechecking it
  requires a single Vite version). It is still linted by ESLint and executed by
  Vitest, which passes.
- pytest prints a third-party deprecation warning from `starlette`/`anyio`
  (`anyio.abc.BlockingPortal` alias). Harmless; upgrade when convenient.
